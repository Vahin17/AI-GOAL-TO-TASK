Pipeline Architecture

Inside the ARDO Intelligence Pipeline

A context-aware planning and orchestration architecture combining RAG, semantic memory, DAG validation, and safety-aware execution.

01

Natural Language Goal Input

Users submit high-level objectives through the frontend dashboard and FastAPI REST endpoints.

Frontend / API
02

RAG Knowledge Retrieval

The system retrieves relevant information from ingested documents and previously stored semantic execution memories.

PostgreSQL + pgvector
03

LLM-Based Goal Decomposition

LLM-based components use the goal and retrieved context to generate a structured task graph.

Gemini / OpenAI / LangChain
04

DAG Validation & Dependency Resolution

The generated task graph is validated for structural correctness, dependency relationships, and acyclic execution order.

Topological Sorting
05

Safety Evaluation & Human Approval

Tasks undergo risk evaluation. High-risk operations require human authorization through the dashboard approval mechanism.

Risk Gates (LOW–CRITICAL)
06

Task Execution & Real-Time Monitoring

The execution engine manages task transitions and communicates execution progress, logs, and status updates through WebSockets.

FastAPI + WebSockets
07

Feedback & Semantic Memory

Execution outcomes, success/failure information, and experiences are stored in semantic memory to inform future planning.

Semantic Execution Memory
Feedback Loop Active: Stage 07 continuously feeds historical execution experiences back into Stage 02 & 03 for self-improving planning.

Core Advantages

Engineered for Reliability

Designed to handle complex real-world workflows without deadlocks or unhandled task failures.

1. Context-Aware RAG Retrieval

Retrieves relevant knowledge and contextual information before generating execution plans, reducing dependence on isolated LLM prompts.

2. Semantic Execution Memory

Stores historical execution experiences, including successes and failures, to inform future planning and help avoid repeated mistakes.

3. Intelligent DAG Generation

Transforms high-level natural-language goals into structured task graphs with explicit dependencies.

4. Dependency Validation

Validates task graphs for cycles and structural inconsistencies before execution.

5. Human-in-the-Loop Safety

Uses risk classification and approval gates to ensure that high-risk operations require human authorization.

6. Resilient Retrieval Architecture

Provides in-memory cosine similarity and deterministic local embedding fallbacks when external database or embedding services are unavailable.

7. Real-Time Execution Monitoring

Uses WebSockets to communicate task status changes, execution logs, and approval requirements to the frontend.

8. Browser Automation Support

Uses Playwright-based browser automation for supported browser workflows, subject to execution policies and safety checks.
