# Phase 2.2: Modular AI Layer & Fallback Rules

## Goal
Implement the abstract LLM provider layer to keep the AI swappable, build the primary concrete provider, and establish the robust rule-based logic framework.

## Context
If an LLM drops the ball, returns a timeout, or a schema violation, the whole planning pipeline could crash. The fallback layer ensures we return a basic 3-step structural graph so the UI never hits an unhandled rendering error. Modularity allows us to switch from LangChain to LiteLLM or raw OpenAI at will.

## File Targets

### `backend/ai/base_provider.py`
- Define abstract base class `LLMProvider` using `abc`.
- Method signature: `def generate_plan(self, prompt: str) -> PlanGraphResponse`.

### `backend/ai/langchain_provider.py` (or default selected)
- Implement `LLMProvider`.
- Setup structured output parsing pointing to `PlanGraphResponse`.
- Include prompt management for the goal-to-task translation.

### `backend/ai/fallback_rules.py`
- Define static dictionaries mapping generic inputs to static generic templates (e.g. init -> execution -> verify).
- Expose `generate_fallback_plan(goal: str) -> PlanGraphResponse`.

## Task Breakdown
1. [ ] Create abstract `LLMProvider` class in `base_provider.py`.
2. [ ] Write the `langchain_provider.py` with the appropriate Pydantic Structured Output parser logic.
3. [ ] Setup initial system instruction prompt inside the provider.
4. [ ] Implement `fallback_rules.py` containing at least one safe, generic React Flow node template if everything fails.

## Verification Steps
- Invoke the static `generate_fallback_plan()` to verify it successfully builds a valid `PlanGraphResponse` object.

## Success Criteria
- Modularity achieved through abstraction; LangChain (or equivalent) provider integrates the Pydantic schemas. 
- A fallback generator seamlessly synthesizes a barebones plan graph.
